# SRZ80 Virtual Computer Rack

Hello there~ 
<img src="docs/ksrsuki.png" width="64" height="64" alt=":ksrsuki:">

SRZ80 started as my failed fantasy console project and somehow turned into a virtual
retro-computer rack. You can build your dream machine from various card
plugins, wire its memory and I/O spaces, assign clocks, and inspect it through an
ImGui debugger (everyone loves ImGui). The same Rust engine also runs headless
for captures and automated checks.

These days, SRZ80 is my playground for all sorts of wonky, unhinged computer
experiments, retro or otherwise. 
<img height="400px" alt="image" src="https://github.com/user-attachments/assets/769c2f0f-24c0-47b4-8f21-a7f1e8bc703b" />

This repo has the host's source code:

- the Rust simulation engine
- the versioned C ABI and plugin SDK
- the desktop GUI debugger (should I really call it a debugger?)
- the headless runner
- the project, state, audio, and video infrastructure shared by both frontends

For now, licensing differences mean cards and tool plugins are distributed separately.
A clean host build has no cards installed. At runtime, SRZ80 finds card libraries in
`bin/plugins/` and GUI tools in `bin/tools/`. I'm working on the licensing side of
things to make it either GPL or AGPL so I can eventually distribute them together.

You can grab the plugins I maintain, including some community contributions, from
[srz80-plugins](https://github.com/LovelyA72/srz80-plugins).

## What it models

In SRZ80 there's no fixed computer layout (which is exactly why SRZ80 failed to become
a fantasy console the first place). Your project defines the address spaces, signal
nets, cards, mappings, and clocks. The engine takes care of:

- byte-addressed spaces with configurable width and unmapped-read values;
- three independent master clocks from 0 Hz to 50 MHz;
- deterministic nanosecond scheduling with fractional-cycle tracking;
- hot and cold reset semantics;
- debugger breakpoints, watchpoints, traces, and side-effect-free inspection;
- deterministic 16-bit stereo mixing at 44.1 kHz; and
- plugin-owned RGBA8 video surfaces.


Plugins implement the hardware. Existing cards include Z80, 65C816, and RISC-V
CPUs; RAM, ROM, and MMU memory; text and V9938 video; several sound chips; and
storage and I/O devices. Those implementations and their third-party emulation
cores are kept outside this host repository.

## Build

I recommend building on Linux. (It's never a better time to have a Linux box!)
You'll need:

- CMake 3.24 or newer
- GCC 12 or newer
- a Rust toolchain for the host target
- the native development packages required by SDL on Linux

SRZ80 uses GCC and single-configuration Makefile generators. MSVC, Visual
Studio, Clang, and Ninja are not supported build paths. CMake downloads pinned
SDL3, Dear ImGui, and nlohmann/json sources during the first configure. See
[third_party/README.md](third_party/README.md) for versions, licenses, and
offline overrides.

### Linux

```sh
cmake --preset gcc-debug
cmake --build --preset gcc-debug -j 4
./build/gcc-debug/bin/srz80_gui
```

To build only the engine and command-line runner:

```sh
cmake -S . -B build/headless -G "Unix Makefiles" \
  -DCMAKE_BUILD_TYPE=Debug \
  -DSRZ80_BUILD_GUI=OFF
cmake --build build/headless -j 4
```

### macOS

I haven't tried building on macOS. The Linux steps may work, but I can't promise
they will.

### Windows with MSYS2 MinGW-w64

**Heads up:** Don't use Linux plugins with a Windows host. They can crash it.

```powershell
rustup target add x86_64-pc-windows-gnu
cmake --preset mingw-debug
cmake --build --preset mingw-debug -j 6
.\build\mingw-debug\bin\srz80_gui.exe
```

The preset uses the GCC toolchain under `C:\msys64\mingw64` and puts its `bin`
directory first for the build process. Windows builds stage the required MinGW
runtime DLLs beside the executables.

### Cross-compile Windows binaries on Linux

Install the MinGW-w64 cross compiler and Rust's Windows GNU target, then run:

```sh
rustup target add x86_64-pc-windows-gnu
cmake --preset mingwcross-debug
cmake --build --preset mingwcross-debug -j 4
```

Use the matching `*-release` preset for stripped release binaries.

## Runtime layout

You can find your builds under the preset's `bin/` directory:

```text
bin/
  srz80_gui[.exe]          desktop debugger
  srz80[.exe]              headless runner
  srz80engine.dll          libsrz80engine.so on Linux
  resources/               fonts and welcome artwork
  plugins/                 card libraries
  tools/                   GUI tool libraries
  licenses/                notices for staged dependencies
```

The engine library owns the rack and loads each card directly. Neither frontend
links against a card implementation. Projects store ROM paths relative to the
project file; plugins, tools, and the default project are resolved relative to
the executable.

Native plugins run in process and are trusted code. Read [SECURITY.md](SECURITY.md)
before installing third-party plugins.

## Command-line runner

The `srz80` executable loads the same projects as the GUI without opening a
window or audio device.

If you're developing a plugin with an AI assistant, the runner is handy for
automated checks.

```sh
srz80 project.json --run 2s --json result.json
srz80 project.json --run 500ms --screenshots captures --wav sound.wav --json result.json
srz80 project.json --script test.json --json -
```

Without `--run` or `--script`, it inspects the project while paused. Scripts can
advance simulated time, inject input, write bytes, assert memory or card
properties, inspect retained console text, and capture video. The runner returns
nonzero on load, execution, assertion, or capture failure.

See [docs/cli.md](docs/cli.md) for the script format, report schema, exit codes,
and capture limits.

## Plugin ABI

[sdk/include/srz80/abi.h](sdk/include/srz80/abi.h) defines ABI v1 with
fixed-width data, size/version headers, opaque handles, explicit status codes,
and function tables. [sdk/include/srz80/engine.h](sdk/include/srz80/engine.h)
exposes the engine boundary used by both applications.

Card plugins remain independent of the UI. GUI tools use the separate contract
in [sdk/include/srz80/tool.h](sdk/include/srz80/tool.h) and must match the host's
Dear ImGui version, allocator, and context. Both plugin types are discovered at
runtime rather than linked into the host.

The engine is written in Rust. It owns scheduling, bus routing, card lifetime,
audio mixing, video surfaces, project loading, debugger state, and the C ABI.
The GUI talks to that boundary through the same handles and status codes exposed
to external hosts.
